# FC Growth 앱 개발 안내

## 실행과 수정

- 현재는 HTML/CSS/일반 JavaScript로 구현한 모바일 우선 웹 프로토타입이다. 네이티브 iOS 앱이나 React 프로젝트가 아니다.
- `python3 scripts/build.py` 후 `python3 scripts/serve.py`로 확인한다.
- 디자인은 `src/app-shell.html`, `src/club.css`, `src/beyond.css`에서 수정한다.
- 기능은 `src/club.js`와 `src/beyond-*.js`에서 수정한다. `dist/`는 생성 결과다.
- `src/app-shell.html`의 자산 토큰은 `src/embedded-assets.json`과 파일로 연결되므로 통합 빌드를 사용한다.
- `beyond-core.js`부터 `beyond-boot.js`까지 하나의 IIFE로 합쳐진다. 부분 파일만 문법 검사하면 정상 코드도 실패할 수 있다.
- 통합 빌드는 기본 화면 → 클럽 코드 → 확장 코드 순으로 조합한다.

## 제품 기준

- Session이 중심이다. 표준 Class Template과 실제 날짜의 Session을 분리한다.
- 기술·전술·피지컬·멘탈·태도 5개 영역에서 축구 훈련의 구체적인 행동을 기록한다. 인성·성격 자체를 점수화하지 않는다.
- 훈련 블록은 목표·시간·진행법·코칭 포인트·관찰 장면으로 구성한다. 클럽 코치가 함께 활용한다.
- 코치는 눈에 띈 선수만 간단히 기록한다. 모든 선수의 평가나 장문 메모를 강제하지 않는다.
- 기록이 없으면 성장 정체나 안정을 단정하지 않는다. 성장 해석은 수업과 관찰 근거를 보여준다.
- 각 페이지는 핵심 먼저, 세부는 더 보기로 제공한다. 일정은 월 단위다.

## 디자인 기준

- 기존 디자인을 유지하며 요청한 부분을 수정한다. 프레임워크 전환을 이유로 전체 화면을 임의로 다시 만들지 않는다.
- 한국어 중심, Pretendard, 화이트 배경과 그린 #156B46~#178A5B.
- 제목 28~32px, 본문 15~17px. 작은 글씨·반복 카드·초록색 도배를 피한다.
- 클래스 탭은 하단 중앙. 하단 탭은 고정하고 내용만 스크롤한다.
- 클래스 제목은 굵게, 아래 수업 목표는 기존 두께를 유지한다.
- 사진 위 글자는 배경에 따라 흰색/검은색 등 읽기 쉬운 대비를 사용한다.
- 앱에 이미 있는 피드·콘텐츠·협찬 화면도 앱 구성의 일부다.

## 백엔드 연결

현재 로그인/DB/API는 없다. 브라우저 메모리의 가상 데이터를 실제 저장 기능으로 설명하지 않는다. 미리보기 껍데기의 위젯 상태 저장 코드는 원생/수업 데이터 저장이 아니다.

첫 구현 범위: 대표 계정과 센터 → 코치 연결 → 훈련 블록/Template → 실제 Session → 출석 확인 → 선택한 선수의 관찰 저장 → 새로고침 후 같은 기록 조회.

필요한 핵심 데이터: Center, User, CenterMembership, Player, GuardianLink, Curriculum, TrainingBlock/Version, ClassTemplate, TemplateBlock, ClassSession, SessionPlayer, Observation, SessionCompletion, GrowthSummary, ClubEvent, FormTemplate/Instance/Response.

- 서버에서 센터 격리와 대표/코치/학부모 권한을 검증한다.
- 모든 선수 관찰은 Session과 연결한다.
- 블록/Template이 수정돼도 과거 수업의 내용은 유지되도록 버전이나 스냅샷을 저장한다.
- 완료 요청 재전송 시 중복 기록을 막는다.
- 실제 참석 여부를 확인하고 출석을 저장한다.
- 부모는 연결된 자녀의 승인된 정보만 본다.
- 현재 폼 링크는 실제 서버 접수 기능이 아니다. 실제 저장·권한·만료·동의 처리를 구현해야 한다.
- AI 분석은 미구현이다. 먼저 근거가 보이는 규칙 기반 요약을 만들 수 있다. API 키는 서버에서 관리한다.
- 현재 iframe/CSP는 미리보기용이다. 실제 인증과 API에 맞는 정식 앱 진입점과 보안 설정을 설계한다.

완료 시 실제 구현한 기능, 테스트 결과, 아직 데모인 기능을 구분해서 알린다.
