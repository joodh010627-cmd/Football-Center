# Football Center

어린이 축구교실을 위한 데이터 기반 운영·협업 웹앱 (MVP 프로토타입).

하나의 관계형 데이터 모델 위에 **두 개의 완전히 분리된 인터페이스**를 올렸다.

| | Coach App | Admin Dashboard |
|---|---|---|
| 대상 | 현장 코치 | 대표 |
| 뷰포트 | Mobile-first (max 430px) | PC / Tablet-first |
| 목적 | 15초 훈련 설계 · 3터치 출결 기록 | 이탈 위험 감시 · 클래스별 마진 관리 |

핵심 루프는 하나다. **코치가 탭한 데이터가 그대로 대표의 의사결정 지표가 되고, 동시에 학부모 리포트와 코치 개인 포트폴리오가 된다.** 코치는 문장을 단 한 글자도 입력하지 않는다.

## 실행

```bash
npm install
npm run dev     # http://localhost:5173
```

우측 상단 `대표 / 코치` 토글로 두 인터페이스를 오간다 (프로토타입 전용 장치. 실제 배포 시 역할은 세션에서 결정된다).

```bash
npm run build      # 타입체크 + 프로덕션 번들
npm run typecheck
```

## 기술 스택

- **React 18 + TypeScript + Vite**
- **Tailwind CSS** — Notion 디자인 시스템 토큰을 `tailwind.config.js`에 그대로 매핑
- **lucide-react** 아이콘
- 상태: `useReducer` + Context. 외부 상태 라이브러리 없음

## 구조

```
src/
├── types.ts                    # 전체 관계형 스키마
├── data/
│   ├── mockData.ts             # 엔티티 + 8주치 출결 이력 생성기
│   ├── churn.ts                # 이탈 위험도 산출 엔진
│   └── selectors.ts            # 조인·집계 (순수 함수)
├── store/AppContext.tsx        # 단일 스토어 + 리듀서
├── lib/                        # 포매터, 알림톡 작성기, cn
└── components/
    ├── ui/                     # Badge · Modal · StatTile · ProgressBar · EmptyState
    ├── coach/                  # 모바일 화면
    └── admin/                  # 대시보드 화면
```

### 데이터 설계

모든 엔티티는 **중첩 객체 없이 외래키 id만 가진 평평한 행**이다. 조인은 데이터가 아니라 `selectors.ts`에서 일어난다. Firebase/Supabase 테이블로 1:1 이관하기 위한 전제다.

```
Student ──┬── classId ──> Class ──> coachId ──> Coach
          └── AttendanceLog ──> sessionPlanId ──> SessionPlan ──> TrainingBlock ×3
```

교체 지점은 `store/AppContext.tsx`의 리듀서 한 곳이다. 각 case 본문을 `await supabase.from(...)` 호출로 바꾸고 현재 로직을 낙관적 업데이트로 남기면 된다. 컴포넌트는 손대지 않는다.

### Mock 데이터

출결 이력은 시드 PRNG(mulberry32)로 생성한다. 매 실행마다 동일한 데이터가 나오고, 원생별 *행동 원형*(`solid` / `steady` / `wobbly` / `fading` / `ghost` / `injured`)에 따라 8주치 출결이 만들어진다.

`lastAttendanceDate`, `status`, `churnScore`는 **손으로 적지 않는다.** 전부 생성된 로그에서 역산된다. 그래서 대시보드의 Red Alert는 언제나 근거를 댈 수 있다.

원생 54명 · 클래스 6개 · 코치 4명 · 훈련 블록 21개 · 행동 태그 21종 · 출결 로그 약 600건.

## Phase 1 구현 범위

### 1. 블록 조립식 훈련 설계 (30-Second Session Builder)

`[웜업 10분] + [스킬 훈련 20분] + [미니 게임 25분]` 3단 슬롯.

- 슬롯을 탭해 포커스 → 라이브러리 카드를 탭하면 채워지고 **다음 빈 슬롯으로 자동 이동**. 블록 3개가 탭 3번이다.
- **[빠른 구성]** 한 번이면 해당 연령대의 표준 커리큘럼 블록으로 3칸이 즉시 채워진다.
- 태블릿/데스크톱에서는 드래그 앤 드롭도 되지만, 모든 동작은 탭만으로 완결된다. 운동장에서 쓰는 화면이기 때문이다.
- 연령대에 맞는 블록이 상단으로 정렬되고, 맞지 않는 블록은 흐리게 처리하되 선택은 막지 않는다.

사용된 블록은 `usageCount`가 올라가며 코치 포트폴리오로 자동 축적된다.

### 2. Coach View — 3-Touch Fast Logging

- **전원 출석으로 시작한다.** 정상적인 수업이면 탭 0회. 코치는 예외만 건드린다.
- 학생 카드 우측 상태 버튼 탭 = `출석 → 결석 → 부상` 순환. 좌측 색상 스트립이 신호등 역할을 한다.
- 카드 본문을 탭하면 **행동 태그 칩이 카드 안에서 인라인으로 펼쳐진다.** 바텀시트도 모달도 쓰지 않는다. 태깅하는 동안 명단을 놓치지 않기 위해서다.
- 태그는 기술/태도/팀워크/피지컬/주의 5개 레일로 나뉜 21종 프리셋. 자유 입력은 없다.
- 결석·부상 처리된 원생의 태그는 자동으로 비운다. 오지 않은 학생의 경기력 기록은 성립하지 않는다.
- **[제출]** → Console + Context 반영 → **학부모 알림톡 시뮬레이션 모달**. 발송될 문면은 탭한 데이터만으로 조립된다.

### 3. Admin Dashboard

**Churn Risk Alert Engine** (`data/churn.ts`) — 가중치 합 100의 4개 축.

| 축 | 가중 | 포화 기준 |
|---|---|---|
| 최근 출석 공백 | 45 | 14일 |
| 30일 결석률 | 30 | 50% |
| 학부모 피드백 지연 | 15 | 21일 |
| 등록 초기 취약성 | 10 | 180일 |

55점 이상이 Red Alert, 78점 이상이 `즉시 조치`. 30일 이상 미출석은 위험군이 아니라 `휴원`으로 분류한다.

점수는 항상 **근거 문장과 함께** 표시된다 ("21일째 미출석 (2주 초과)", "학부모 피드백 34일 지연"). 대표가 숫자를 의심하지 않고 바로 전화를 걸 수 있어야 하기 때문이다.

`[CS 조치 완료]`를 누르면 `CsAction`이 기록되고 큐에서 빠지며, 학부모 접촉일이 갱신되어 점수에 즉시 반영된다.

**Class Retention & Margin Table** — 공헌이익 기준 정렬. 재등록률 80% 미만은 적색, 마진율 25% 미만은 경고색으로 뜬다. 정원 충족률·출석률·코치 만족도를 한 행에서 비교한다.

**부수 패널** — 코치별 표준 커리큘럼 준수율(품질 통제), 현장 기록 피드(프로세스 준수 증거), 원생 성장 리포트 모달(출결 스트립 + 태그 누적 + 코멘트 이력).

## 설계 판단 몇 가지

**출석률에서 부상은 제외한다.** 부상을 결석으로 세면 정직하게 기록한 코치가 지표에서 손해를 본다. 그러면 코치는 전원 출석으로 찍기 시작하고 데이터는 죽는다.

**같은 날 재제출은 덮어쓴다.** 중복 집계 대신 갱신이다.

**제출 후에도 draft를 유지한다.** 알림톡 모달이 명단 위에 뜨는데, 여기서 draft를 비우면 모달 아래 화면이 언마운트된다.

**기록 충실도를 KPI로 올렸다.** 태그·코멘트가 붙은 로그의 비율이다. 이 숫자가 떨어지면 대시보드의 다른 모든 숫자를 믿을 수 없다는 뜻이다.

## 알려진 한계

- 상태는 메모리에만 있다. 새로고침하면 초기화된다 (영속화는 백엔드 연동 시점의 일).
- 재등록률은 클래스 고정값이다. 실제로는 결제 이력에서 산출해야 한다.
- 알림톡은 시뮬레이션이다. 실제 발송 연동 없음.
- 인증/권한 없음. 역할은 토글로 전환한다.
